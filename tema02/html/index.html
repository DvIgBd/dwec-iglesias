¿Por qué casi todos los navegadores comparten motor?

Crear y mantener un motor de renderizado es carísimo, ya que tiene que interpretar HTML, CSS y JavaScript cumpliendo todos los requisitos a pesar del constante cambio. Este es uno de los motivos principales por los que las empresas optan por Chromium y construir su navegador encima. Los únicos grandes que se quedan fuera son Firefox (motor Gecko) y Safari (Webkit). Para quien desarrolla una web, esto tiene una parte buena y una mala. La buena es que si funciona en Chrome probablemente funcione en casi todos los demás. La mala es que eso no basta, ya que Firefox y Safari pueden no ser compatibles.

¿En qué navegadores probaría una web?

Lo mejor sería intentar hacer una web que sea compatible con los tres motores principales (Blink, Webkit, Gecko), aunque si debemos elegir un navegador con el que probar nuestro código, elegiría Chrome, ya que es el más utilizado. A día de hoy la forma más común de acceso a un navegador es mediante el móvil, por lo que adaptaría la página también a Safari.

Un caso de compatibilidad real

Hay 4 casos que son bastante notorios por su incompatibilidad:

  1. Vibración del móvil con navigator.vibrate(): esta función está pensada para hacer vibrar el teléfono tras una acción. Funciona en Chrome y en Edge, pero no en Firefox y Safari.

  2. Personalizar el la etiqueta select con CSS: sirve para dar estilo completo a los desplegables, que hasta ahora eran casi imposibles de personalizar. Chrome lo soporta desde la versión 135, Safari desde la 27 y Firefox todavía no.

  3. Web Bluetooth: permite que una web se conecte a dispositivos Bluetooth cercanos. Chrome lo tiene desde la versión 70 y Edge desde la 79, mientras que Firefox y Safari no.

  4. Cuentagotas con la API EyeDropper: abre una herramienta para elegir cualquier color de la pantalla. Está en Chrome y Edge de escritorio desde la versión 96, pero no Chrome, Firefox y Safari.
